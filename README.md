# HealthLife

HealthLife 是一个面向手机端的个人健康追踪工具，只聚焦运动、饮食、睡眠和体重四类数据。目标是降低每日记录负担，并通过周／月趋势和分析 JSON 帮助用户回顾生活习惯。

项目采用原生 HTML、CSS 和 JavaScript，本地优先，不提供账号、服务端存储或自动同步。正式页面位于 `docs/`，可通过 GitHub Pages 发布，并支持 PWA 离线使用。

## 核心功能

- 今日：用日历切换日期，快速记录四类数据，并根据简单的每周模板记录实际训练；内置文字引导保留为备用入口。
- 运动：按 Keep 跟练、跑步和其他运动分流，只展示当前场景需要的字段，并可把最近一次同场景训练复制到未保存表单。Apple Watch 可选填平均心率，跑步可选填距离并预览配速。备用文字训练继续支持逐组完成、休息、替代动作、历史样本、保守进阶建议、不适反馈和持久撤销。
- 饮食：在设置中维护个人常用食材和默认份量，记录时按类型分区多选并按需调整本餐份量；手机录入标题直接显示所选日期，不重复提供日期控件，布局紧凑且不产生横向滚动。当天已有餐次可直接载入补充，三餐重复新增前必须明确确认，加餐允许多条。食材标签显示默认份量和本份蛋白质估算，早餐、午餐和晚餐会显示蛋白质建议范围，蛋白质参考值可选，外卖、堂食和临时食物始终可以直接写文字。
- 睡眠：记录入睡、起床、质量、夜醒次数和备注，自动计算跨日时长。
- 体重：每天最多一条，支持可选体脂率，趋势展示原始值与 7 日均重。
- 趋势：最近 7 天或 30 天的四类核心汇总，不对缺失日期补零。
- 记录：按类型和月份查看、编辑或删除明细，删除后提供短时撤销。
- 设置：首屏直接导出完整备份和分析数据，并查看最近备份状态；恢复备份、常用食材、每周训练模板和安装更新分别进入二级页面。

步数、饮水、工作排班、加班计划、每日计划状态、改期、连续记录、饮食健康评分、活动热量和最高心率不属于当前产品范围。

## 本地数据边界

- 正式数据只保存在当前浏览器的 `localStorage` 中，不上传到 GitHub。
- 当前数据使用 schema v12 和独立键 `healthlife:data:v12`。首次打开时优先迁移经过完整校验的 v11 本地数据；缺少 v11 时才链式迁移 v10，并保留原 v11 和已有 v10 键。v1 至 v9 不读取、不迁移。
- 不同设备、浏览器、普通模式和无痕模式使用不同的数据空间。
- 清除网站数据、卸载浏览器或更换设备可能导致记录丢失，应提前导出完整 JSON 备份。
- 完整备份使用 v12；导入前整体校验 v12，或先把有效 v11／v10 备份迁移为 v12。覆盖非空本地数据前会先下载当前完整备份。
- 仓库中的测试和演示内容必须完全虚构，不得提交真实健康记录。
- 本项目只提供个人记录和趋势观察，不提供医疗诊断或治疗建议。

## 使用方式

1. 在“今日”通过周日历选择日期；未来日期不能新增健康记录。
2. 点击运动、饮食、睡眠或体重卡片录入数据。
3. “今日训练”读取每周训练模板。点击“记录实际训练”进入 Keep、跑步或其他运动表单；需要纯文字动作提示时再进入“备用文字训练”，结束确认后才生成正式记录。
4. 先在“设置 → 常用食材”录入经常吃的食材、默认份量和可选蛋白质参考值；之后记录饮食时选择食材即可，份量变化时只改本餐数值。修改已有参考值时默认只影响以后记录；如果是在纠正原来填错的数值，可以查看影响预览后主动同步兼容的历史估算并在保存后短时撤销。
5. 外卖、堂食或临时食物可直接写在自由文字中。软件不会从文字自动猜营养；存在自由文字或无参考值食材时，会明确显示未完整估算。
6. 在“趋势”查看 7 天／30 天汇总，在“记录”编辑或删除明细。
7. 在“设置”首页直接导出完整备份或分析数据；从“恢复完整备份”进入文件预览和替换流程，从“每周训练模板”调整默认推荐。

## 项目结构

```text
docs/               GitHub Pages 页面与浏览器端模块
tests/              Node.js 标准库测试
test-data/          纯虚构历史演示数据，不代表当前兼容格式
AGENTS.md           项目开发规范
DATA_MODEL.md       schema v12 字段、迁移与统计口径
UX_INTERACTION.md   当前 UX 交互说明
ROADMAP.md          项目真实进度
```

## 本地验证

```bash
npm run check
npm test
python3 -m http.server 8000 --directory docs
```

然后访问 `http://localhost:8000/`。

## 发布

正式页面位于 `docs/`。推送远端和将 GitHub Pages 发布源设置为 `main` 分支的 `/docs` 目录属于公开发布操作，需要单独确认。
